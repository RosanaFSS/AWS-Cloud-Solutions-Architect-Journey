<h2  align="center" class="bold" style="font-weight: bold">AWS IAM, Creating a Password Policy and an IAM Role</h2>
<p align="center">
Policies and Permissions in IAM<br>

AWS Identity and Access Management (IAM) policies play a crucial role in securing and managing cloud resources. These policies define fine-grained permissions, allowing you to grant or restrict access to specific AWS services and resources. Manage access in AWS by creating policies and attaching them to IAM identities (users, user groups, or roles) or AWS resources. A policy is an object in AWS that, when associated with an identity or a resource, defines its permissions. AWS evaluates these policies when an IAM security entity (user or role) makes a request. The permissions in the policies determine whether the request is allowed or denied. Most policies are stored in AWS as JSON documents. AWS supports six types of policies: identity-based policies, resource-based policies, permission boundaries, Service Control Policies (SCPs) in Organizations, Access Control Lists (ACLs), and session policies.<br>

IAM Roles<br>

IAM roles are a way to delegate access to AWS resources to trusted entities without the need to share long-term credentials or create specific user accounts. IAM roles consist of a trust policy and a permission policy, which define who can assume the role and which resources they can access. IAM roles use temporary credentials generated by the AWS Security Token Service (STS). IAM roles can be used for various use cases, such as granting access to users from another AWS account, federated users, applications, or AWS services.
</p>
